Phase-2: Dockerize ML Application
======================================================

Traditional ML flow:
dataset->train->model evaluation->prediction

Production Ready ML Application
Saved Model -> Python App -> Rest API -> Automated Test -> Docker Container ->CI/CD 
Can be tested, deployed, accessed by clients and maintained consistently

Why do we need Docker?
-Imagine right now ML Applicationis working on your macbook, but fails on another engineer laptop that runs it on a Linus/windows server

Possible reasons of failure:
-Different Python Versions
-Missing python packages
-Different OS dependencies

Docker helps package your application code, runtime, dependencies and startup instructions into a standardized image

4 major requirements:
-Dockerfile- Instructions for packaging the ML application
-Image- packaged reusable application artifact
-Container- running instance of that image
-Port Mapping- Makes the API inside the container accessible from your system


images vs containers: 
image is a package and containers run images

Commands for Docker:
1. docker ps = print all runnnig containers
2. docker ps -a = print all active/non-active containers
3. docker build -t cse-mlops .
//-t for name of image and cse-mlops is the name

NOTE: everything will be sared thru image except .dockerignore

4. docker images = print locally available docker images
5. Start the container:
docker run -d --name iris-ml-api -p 8000:8000 cse-mlops
//-d for detach to not print the logs in terminal
//-p for Port and --name for name of container

What is CI/CD?
-CI: Continuous Integration: Automated validates code changes through tests and build checks
-CD: Continuous Delivery: Keeps changes ready for release with production release potentially requiring approval
-CD: Continuous Deployment: Automatically releases changes to production when all required checks pass


Automated Testing
- Automated Testing catches issues before a change moves to production
